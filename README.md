# Legal Document Summarization

Automatic summarization of long legal contracts (NDAs, SLAs, supply/license/service agreements) so lawyers can review key points faster. The project fine-tunes transformer models (**BART** and **T5**) for legal-language summarization and compares them against an **extractive LexRank** baseline, evaluating summary quality with ROUGE and a custom clause-preservation metric.

**Author:** Rahul Deshpande

---

## Project Scope

- Collect legal contracts from **CUAD** (Contract Understanding Atticus Dataset)
- Preprocess with sentence-aligned chunking and named entity tagging
- Fine-tune BART and T5 with Hugging Face
- Compare extractive (LexRank) vs. abstractive (BART/T5) approaches
- Evaluate with ROUGE-1/2/L and clause preservation; summarize and validate 10 contracts

## Pipeline Overview

1. **Data loading**: CUAD's SQuAD-style JSON (`CUADv1.json`) is downloaded from the Atticus Project GitHub repo. It contains 510 contracts, each with full text and expert-labeled spans across 41 clause categories.
2. **EDA**: Contract length distribution, clause-category coverage, and clauses per contract. Most contracts far exceed a single BART/T5 input window.
3. **Preprocessing**
   - **Chunking**: spaCy sentence segmentation, then ~380-word chunks with a 2-sentence overlap (never truncating mid-sentence).
   - **NER tagging**: spaCy `en_core_web_sm` extracts `ORG`, `PERSON`, `DATE`, `MONEY`, `GPE`, `LAW` per chunk.
4. **Extractive baseline**: LexRank implemented from scratch (TF-IDF sentence vectors, cosine-similarity graph, PageRank), selecting the top 5 sentences in original order.
5. **Reference summaries**: CUAD has no human-written document summaries, so a *silver-standard* reference is built by concatenating each contract's labeled clause spans in a priority order (up to 150 words).
6. **Fine-tuning**: `facebook/bart-base` and `t5-base` trained with `Seq2SeqTrainer` on an 80/10/10 train/validation/test split.
7. **Hierarchical inference**: each chunk is summarized independently, then the chunk summaries are combined into one document-level summary (with an optional second pass).
8. **Evaluation**: ROUGE-1/2/L (F1) and a clause-preservation score (content-word recall of each labeled clause in the summary, counted as preserved at >= 0.5).

## Training Configuration (BART and T5)

| Parameter | Value |
|---|---|
| Learning rate | 3e-5 |
| Per-device train/eval batch size | 2 |
| Gradient accumulation steps | 2 (effective batch size 4) |
| Epochs | 2 |
| Max input / target length | 512 / 128 tokens |
| Mixed precision (fp16) | Off (CPU training) |

T5 additionally uses the `"summarize: "` input prefix.

## Results (10-Contract Validation Set)

| Method | ROUGE-1 | ROUGE-2 | ROUGE-L | Clause Preservation |
|---|---|---|---|---|
| Extractive (LexRank) | 0.193 | 0.057 | 0.118 | **0.400** |
| BART (fine-tuned) | **0.400** | **0.201** | **0.273** | 0.247 |
| T5 (fine-tuned) | 0.240 | 0.105 | 0.170 | 0.202 |

**Takeaways**

- BART gives the best ROUGE scores across the board.
- LexRank preserves labeled clause language best, since it copies sentences verbatim.
- T5 underperforms, and its raw output showed repetitive text on sample chunks. This is likely due to only 2 training epochs plus unconstrained decoding. Adding `no_repeat_ngram_size` / `repetition_penalty` to `model.generate()` is a low-cost fix that needs no retraining.

## How to Run

1. Open `legal_doc_summarization.ipynb` and run the cells in order. CUAD is downloaded automatically on the first run.
2. **Fine-tuning cells (Section 15)** are commented out in the submitted notebook because training is slow. To retrain, uncomment them, set `MODEL_NAME` to `"facebook/bart-base"` or `"t5-base"`, and run once per model. Checkpoints are saved to `./final_model/<model_name>`. On a GPU, set `fp16=True` and consider larger batch sizes and more epochs.
3. **Section 21** loads the saved checkpoints from `./final_model/` and runs the extractive vs. BART vs. T5 comparison on the 10 validation contracts. It writes `processed/final_comparison_extractive_bart_t5.pkl` and `processed/final_comparison_scores.csv`.

NER is run on a 20-contract sample by default to keep runtime short. Change `SAMPLE_SIZE` in Section 9.1 to process the full corpus.

## Limitations

- **Silver-standard references**: reference summaries are built from labeled clause spans, not written by humans, so ROUGE rewards span overlap more than a comparison against free-form human summaries would.
- **CUAD taxonomy**: CUAD has no literal "Confidentiality" or "Indemnification" categories. Closest substitutes (Cap On Liability, Uncapped Liability, Non-Disparagement, Audit Rights, Governing Law, Termination For Convenience) were used.
- **Small validation set**: 10 contracts, so results are directional rather than statistically robust.
- **Limited training**: both models were trained for 2 epochs on CPU, which likely understates their achievable performance, especially for T5.
- **Coherence not yet scored**: the `coherence_rating_1to5` column in the comparison table is left for manual review.
- **Word-count chunking**: chunk sizes use a word-count proxy for the token budget; chunks are truncated by the real tokenizer at model input time.
